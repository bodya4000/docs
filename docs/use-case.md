# Варіанти використання: фінансова аналітика та звітність

## Актори

| Актор | Опис |
|--------|------|
| **Фінансовий аналітик** | Побудова звітів, фільтри, експорт, робота з показниками. |
| **Керівник** | Перегляд узагальнених результатів без глибокої підготовки даних. |

## UC2. Сформувати квартальний фінансовий звіт

**Актори:** Фінансовий аналітик (основний); керівник цей сценарій типово не виконує.

**Передумови:** Є права на формування звітів; визначено рік і квартал.

### Основний порядок дій

1. Аналітик обирає шаблон квартального звіту та календарний квартал.
2. Система збирає показники за правилами шаблону (суми, підсумки, порівняння з попереднім кварталом за потреби).
3. Система формує чернетку звіту з таблицями та графіками в попередньому перегляді.
4. Аналітик перевіряє коректність; за потреби коригує параметри та повторює кроки 2–3.

### Альтернативні шляхи

- **А1.** Використання збереженого набору фільтрів організації — швидший вибір на кроці 1.
- **А2.** Звіт зберігається як чернетка без публікації для керівника.

### Винятки

- **В1.** Неповний набір обов’язкових показників — звіт не формується; виводиться список відсутніх статей.
- **В2.** Конфлікт версій даних — система пропонує повторне зчитування або фіксацію на знімку на певний час.

### Післяумови

Існує сформований квартальний звіт (чернетка або готова версія) у системі.

## UC3. Експортувати квартальний звіт у PDF

**Актори:** Фінансовий аналітик (типово); керівник — якщо надано право експорту готових звітів.

**Передумови:** Існує згенерований квартальний звіт (UC2).

### Основний порядок дій

1. Користувач відкриває готовий або затверджений квартальний звіт.
2. Користувач обирає «Експорт → PDF» і параметри (орієнтація, чи включати графіки).
3. Система рендерить макет і формує файл PDF.
4. Система пропонує зберегти або відкрити файл; факт експорту фіксується в журналі.

### Альтернативні шляхи

- **А1.** Експорт у фоні для об’ємних звітів — користувач отримує сповіщення після завершення.
- **А2.** Відправка PDF на корпоративну пошту згідно з політикою безпеки.

### Винятки

- **В1.** Перевищено ліміт розміру або часу генерації — повідомлення та пропозиція скоротити розділи.
- **В2.** Політика DLP блокує вивантаження — відмова з кодом причини.

### Післяумови

PDF створено локально або передано згідно з політикою; у журналі є запис про експорт.

## UC4. Застосувати фільтри та порівняння періодів для аналізу

**Актори:** Фінансовий аналітик.

**Передумови:** UC1 виконано або доступний модуль аналітики.

### Основний порядок дій

1. Аналітик задає базовий і порівняльний періоди та набір показників.
2. Система обчислює відхилення та частки змін.
3. Система оновлює таблиці та діаграми.
4. Аналітик інтерпретує відхилення; інтерпретація лишається поза межами системи.

### Альтернативні шляхи

- **А1.** Збереження пресету фільтрів для регулярних оглядів.
- **А2.** Порівняння лише табличне без графіків для швидкості.

### Винятки

- **В1.** Порівнювані періоди несумісні (різна структура статей) — попередження та пропозиція узгодженого знімка класифікатора.

### Післяумови

На екрані відображається порівняльний аналіз за обраними правилами.

## UC5. Переглянути узагальнений квартальний звіт (режим керівника)

**Актори:** Керівник.

**Передумови:** Аналітик опублікував або надав доступ до версії звіту; керівник має право перегляду.

### Основний порядок дій

1. Керівник відкриває розділ «Звіти» та обирає квартальний звіт.
2. Система показує ключові KPI, підсумкові таблиці та обрані графіки без редагування структури.
3. Керівник переглядає матеріали; за наявності прав ініціює UC3.

### Альтернативні шляхи

- **А1.** Перегляд лише мобільної скороченої версії.
- **А2.** Перехід до деталізації через обмежений drill-down, якщо політика дозволяє.

### Винятки

- **В1.** Звіт знято з публікації — інформаційне повідомлення та остання доступна версія або відсутність даних.
- **В2.** Прострочена сесія — повторна автентифікація.

### Післяумови

Керівник отримав актуальну для нього картину за кварталом.
